# Changelog

Changes from upstream `cursor/plugins` `pstack/skills/reflect`.

- Named where to read `pstack-models.mdc`: `~/.cursor/rules/pstack-models.mdc`, then `~/.pstack/pstack-models.mdc`.
- Added a fallback when the harness has no Cursor `Task` tool or rejects `subagent_type`.
- Skill edits now also name `.agents/skills/`, `.claude/skills/`, and `.grok/skills/` as destinations, alongside the Cursor paths.
- Reviewer prompts treat a `Read` of `SKILL.md` under those harness directories as a skill the transcript used.
- On Amp, step 1 uses this thread's URL (`Amp Thread URL`, or `https://ampcode.com/threads/<thread ID>`) as the transcript instead of an `agent-transcripts/` file, because Amp keeps no transcript files on disk. The skill says how to detect Amp: the system prompt names it, or the `create_thread`, `read_thread`, and `send_thread_message` tools exist.
- Step 1 passes a digest when the system prompt names no `agent-transcripts/` directory, not only when no file matches. Upstream left harnesses without that directory, such as Claude Code, with no instruction.
- Added "On Amp: child threads that report back" to step 2. The three reviewers run as child threads (`create_thread`, orb, `intent: independent-review`, `archive_when_done: true`) that read the parent with `read_thread` and report with `send_thread_message` in one shape: `reflect <lens> findings: <N>`, then the numbered list. The parent ends its turn instead of polling, because each reply starts a new turn. On each later turn, including a user message, it starts no new reviewers. A lens counts from its `reflect <lens> findings` reply or, when that header never arrives, from the settled child's final response via `read_thread` before the parent waits again. It ends the turn only while a lens has not counted. Amp's `Task` subagents cannot call `read_thread`, and child threads keep reviewer work out of the parent's context. The section also maps the Cursor model slugs to Amp model keys, says the child orb sees the default branch and not uncommitted work, and falls back to `Task` with a digest when `create_thread` is missing.
- Step 3 says how to run the synthesizer on Amp: `Task` without `subagent_type` or `model`, with each child's reply inlined as that reviewer's output. Drop a leading `reflect <lens> findings: <N>` line when the reply has one, and keep the first line when it does not.
- Step 5 treats Amp's read-only `~/.cache/amp/global-skills/` like `plugins/cache/`, routes the substantive-edit, description-tuning, and new-skill rows to Amp's `building-skills` skill because Amp has no `create-skill`, and calls `reload_skills` after edits.
- The three reviewer prompts read an Amp thread URL with `read_thread` (context `full`) and count a `skill` tool call that loads a skill as using it, because Amp loads skills with that tool instead of a `Read` of `SKILL.md`.
